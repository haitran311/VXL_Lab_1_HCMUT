Hướng Dẫn Build STM32 Bằng VS Code

1. Cách Build Project

Tôi đã thiết lập hệ thống tự động gọi trình biên dịch của STM32CubeIDE 1.7.0 ngay bên trong IDE này. Để build, bạn chỉ cần:

  • Nhấn tổ hợp phím Ctrl + Shift + B (hoặc mở Command Palette và gõ Run Build Task).
  • Một danh sách các project (lab1ex1, lab1ex2...) sẽ hiện ra. Bạn chọn project muốn build.
  • Kết quả build (file .hex, .elf) sẽ nằm trong thư mục Debug/ của từng project, sẵn sàng để bạn nạp vào Proteus.

2. Nguyên Nhân Gây Lỗi Trước Đó

Lỗi đã gặp: ld.exe: cannot open linker script file ... Vi ??i???u khi???n ... STM32F103C6UX_FLASH.ld: No such file or directory

Giải thích: Workspace của bạn nằm trong đường dẫn có chứa dấu tiếng Việt (Vi điều khiển). Trình biên dịch GCC cũ (version 9) đi kèm với STM32CubeIDE 1.7.0 gặp lỗi giải mã ký tự Unicode khi được gọi chạy ngầm (headless build) từ PowerShell. Do đó, đường dẫn tuyệt đối bị biến dạng thành Vi ??i???u khi???n, khiến trình liên kết (Linker) không tìm thấy file cấu hình bộ nhớ .ld.

3. Cách Tôi Đã Khắc Phục

Tôi đã sửa file cấu hình .cproject của tất cả các lab. Thay vì dùng đường dẫn tuyệt đối (chứa thư mục "Vi điều khiển"), tôi chuyển thành đường dẫn tương đối: ../STM32F103C6UX_FLASH.ld

Vì đường dẫn tương đối không bao gồm tên thư mục gốc, trình biên dịch GCC có thể đọc được file bình thường mà không bị lỗi font chữ.

4. Lưu Ý Khi Tạo Project Mới (Quan Trọng)

Nếu sau này bạn tạo thêm một bài Lab mới (ví dụ lab1ex5) bằng STM32CubeIDE 1.7.0, bạn sẽ lại gặp lỗi tương tự nếu build bằng VS Code. Để khắc phục triệt để cho project mới, hãy làm 1 trong 2 cách sau:

Cách 1: Đổi trực tiếp trên giao diện STM32CubeIDE (Dễ nhất)

  1. Mở project bằng STM32CubeIDE.
  2. Nhấp chuột phải vào tên Project -> Chọn Properties.
  3. Mở C/C++ Build -> Settings -> tab Tool Settings.
  4. Chọn mục MCU GCC Linker -> General.
  5. Ở ô Linker Script (-T), xóa ${workspace_loc:/${ProjName}/STM32F103C6UX_FLASH.ld} và sửa thành:
    ../STM32F103C6UX_FLASH.ld
  6. Nhấn Apply and Close.

Cách 2: Đặt workspace ở thư mục không dấu

Cách tốt nhất để lập trình C/C++ là bạn nên di chuyển toàn bộ thư mục THANH HAI\HK261\Vi điều khiển\VXL_Lab_1 sang một đường dẫn hoàn toàn không có dấu và không có khoảng trắng. Ví dụ: C:\Projects\VXL_Lab_1. Điều này sẽ giúp bạn tránh được 99% các lỗi liên quan đến trình biên dịch sau này.
